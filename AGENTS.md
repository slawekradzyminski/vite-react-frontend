## Deployment asset rule

- In `awesome-localstack`, the gateway owns `/images/...` and serves that path directly from its own mounted volume.
- Do not place frontend-only branding assets under `/images/...` if they must work behind the gateway.
- Use a separate public prefix such as `/branding/...` for frontend logos, favicons, and similar files.
- If deployed branding assets 404 while they exist in the frontend image, inspect the gateway config before changing Vite or nginx in this repo.

## Mutation testing: two layers

- Layer 1 uses framework-generated mutants from StrykerJS. Layer 2 uses
  requirement-driven semantic mutants generated by the agent.
- Run normal verification first, then Layer 1 for configured changed code. Add
  Layer 2 only for changed high-risk behavior; do not combine the two result
  sets into one mutation score.

### Layer 1: framework-generated mutants (StrykerJS)

- Run `npm test` first, then `npm run test:mutation` after changing SSO, runtime URL, SSE behavior, or their tests.
- Treat `NoCoverage` as a reachability gap and `Survived` as an assertion gap. For each meaningful survivor, add a test that passes on the original code and fails on that mutant.
- Prioritize authentication/PKCE invariants, callback failure paths, redirect safety, and lossless stream parsing. Do not add brittle implementation-detail assertions solely to increase the score.
- The initial score is advisory. On pull requests, reject new meaningful survivors in changed high-risk code; keep broader mutation-score trend checks outside the fast test loop.

### Layer 2: agent-generated semantic mutants

- After normal tests and Stryker, generate one to three requirement-driven semantic mutants for changed SSO/authentication, retry, redirect, protocol, streaming, compatibility, or stateful behavior.
- Prefer plausible ordering, state-machine, transport-boundary, policy, and multi-line data-flow mistakes over operators Stryker already covers. State the violated contract and observable difference for each patch.
- Apply candidates only in a disposable copy or worktree. Require successful typechecking/build; compilation failure is invalid, not killed. Run the smallest relevant green Vitest target.
- Review survivors for equivalence and requirement validity. Add a contract test only when it passes on the original and fails on the frozen mutant; never couple a test to private syntax merely to improve a score.
- Keep the challenge bounded to changed high-risk behavior and report killed, survived, invalid, and equivalent candidates separately.
